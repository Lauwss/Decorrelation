# 服务器使用规范（A100 / Alex 训练服务器）

> 整理自：① 郑德重 6 月 25 日版《A100 服务器环境与缓存规范》；② `docs/服务器运维的知识管理.md`（当前 Alex 训练机）。
> 核心原则：**系统盘空间有限，一切大文件（conda 环境、pip/HF/Torch 缓存、数据集、模型权重、临时文件）都必须落在 `/data` 盘。**
> 注：两台服务器路径略有差异，见各节标注。

## 1. 路径约定

**A100 服务器**：

- 公共 Miniconda：`/data/shared/miniconda3`
- conda 虚拟环境默认路径：`/data/shared/miniconda3/envs`（正常 `conda create -n myenv python=3.11` 即可，不会写系统盘）
- **ssh 连接默认进入的是 `/home/data` 路径，请先切到 `/data` 路径下再操作。**

**当前 Alex 训练机**（源自运维知识管理）：

- 系统 conda：`/data/conda`，初始化：`/data/conda/bin/conda init {YOUR_SHELL}`
- mlusers 组成员可在 `/data/conda_envs` 创建/管理/删除环境（base 环境除外）
- 个人数据（ONLY）家目录：`/fast/home`
- 共享工作区（mlusers 可创建/修改/删除）：`/data/shared`
- ⚠️ `/data/shared` **不在日常备份范围内**，重要数据请自行多处备份

## 2. 缓存配置的生效方式

公共缓存配置文件：`/etc/profile.d/00-data-shared-cache.sh`

- 普通 bash 终端自动加载；若未生效，手动执行：

```bash
source /etc/profile.d/00-data-shared-cache.sh
```

- 或重新登录服务器。
- 通过 Jupyter、systemd、后台任务平台等**非普通 shell** 启动时，必须在启动脚本中显式加入上面这行 `source`。

## 3. 缓存与临时目录（按用户名自动落到 /data）

以用户 `ecs-user` 为例（其他用户自动替换为 `/data/cache/$USER/...`）：

```text
TMPDIR=/data/tmp/ecs-user
PIP_CACHE_DIR=/data/cache/ecs-user/pip
HF_HOME=/data/cache/ecs-user/huggingface
HF_HUB_CACHE=/data/cache/ecs-user/huggingface/hub
TRANSFORMERS_CACHE=/data/cache/ecs-user/huggingface/transformers
HF_DATASETS_CACHE=/data/cache/ecs-user/huggingface/datasets
TORCH_HOME=/data/cache/ecs-user/torch
TORCH_EXTENSIONS_DIR=/data/cache/ecs-user/torch_extensions
CUDA_CACHE_PATH=/data/cache/ecs-user/nv/ComputeCache
TRITON_CACHE_DIR=/data/cache/ecs-user/triton
MODELSCOPE_CACHE=/data/cache/ecs-user/modelscope
```

conda / pip 缓存：

- conda 包缓存：`/data/cache/$USER/conda/pkgs`，fallback `/data/shared/cache/conda/pkgs`
- conda fallback 配置：`/data/shared/miniconda3/.condarc`
- pip 缓存：`/data/cache/$USER/pip`，fallback 配置 `/etc/pip.conf`

## 4. 检查配置是否生效

```bash
echo $TMPDIR
echo $PIP_CACHE_DIR
echo $HF_HOME
echo $TORCH_HOME
conda info
python -m pip cache dir
```

预期输出：

```text
temporary directory : /data/tmp/$USER
package cache       : /data/cache/$USER/conda/pkgs 或 /data/shared/cache/conda/pkgs
envs directories    : /data/shared/miniconda3/envs
pip cache dir       : /data/cache/$USER/pip
```

## 5. 下载与 git clone 注意事项

`git clone` / `wget` / `curl` 默认下载到**当前目录**，因此：

- 不要在 `~`（家目录）下载大文件或克隆模型仓库；
- 先进入数据盘目录再下载：`cd /data/你的项目目录`；
- 需要显式指定目标路径时：

```bash
git clone <repo_url> /data/你的项目目录/ref_project/xxx
wget <url> -O /data/你的项目目录/downloads/file.bin
curl -L <url> -o /data/你的项目目录/downloads/file.bin
```

## 6. 推荐使用习惯

1. 新开终端先检查 `echo $TMPDIR`、`conda info`；
2. 项目、数据集、模型权重尽量放在 `/data` 下；
3. 不在 `~` 目录执行大文件下载、模型仓库克隆或大规模解压；
4. 非交互式启动（Jupyter / systemd / 后台任务）记得在启动脚本里 `source /etc/profile.d/00-data-shared-cache.sh`。

## 7. GPU 任务必须通过 Slurm 提交

GPU 计算任务**禁止直接在前台/后台裸跑**，必须用 `sbatch` 提交；裸跑会与其他任务互相挤占显存导致 OOM，且进程会随 SSH 断开被清理。

- 系统装有 `gpu-rogue-kill` 守护（`/usr/local/sbin/gpu_rogue_kill.sh` + systemd timer），**每分钟清理一次绕过 Slurm 的 GPU 任务**，裸跑必被 kill
- **不涉及 GPU 的任务不要提交 Slurm**（会白白占用队列）；平时怎么跑就怎么跑
- 系统 RAM 硬限制 **72GB**（`--mem` 请勿超过 72G）；CPU/内存暂无其他配额，请合理使用
- 便捷工具：`turm`（TUI 队列查看）、`shelper`（常用命令 wrapper，直接输入即可用）
- 并发配额：
  - GPU 同时总 jobs：**4**；每用户同时 jobs：**4**；每用户提交上限：**30**
  - Fairshare 已启用（`PriorityWeightFairshare=100000` 等）：近期占用资源过多的用户会被让道给偶尔使用的用户
- 分区：`gpu`（单节点 `yumingz5-linux-ml`，48 核 / 150GB 内存）
- GPU 共享：`gpushare` 插件，节点共 4 份额，用 `--gres=gpushare:1` 申请
- 常用 SBATCH 参数：

```bash
#SBATCH --partition=gpu
#SBATCH --gres=gpushare:1
#SBATCH --cpus-per-task=10
#SBATCH --mem=48G
#SBATCH --time=72:00:00
#SBATCH --output=/dev/null
#SBATCH --error=/dev/null
```

- 提交：`sbatch Slurm/train.slurm`；查看队列：`squeue -u $USER`；取消：`scancel <jobid>`
- 训练详情和 Python 错误查看 `results/ckpt/<ckpt_name>/train.log`；Slurm 外层 `.out/.err` 默认丢弃。
- 脚本开头必须 `source /etc/profile.d/00-data-shared-cache.sh`（见第 2 节）
- 注意：gpushare 只约束经 Slurm 提交的任务；若发现他人进程绕过 Slurm 直接占满 GPU（`nvidia-smi` 可见），作业脚本内应做显存检查等待（参考 `Slurm/train.slurm`）

## 8. 其他工具（源自运维知识管理）

- **Linuxbrew**：装新工具可用，首次在 `~/.zshrc` 追加：

```bash
echo 'eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv zsh)"' >> ~/.zshrc
eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv zsh)"
```

- **Docker**：非 root 访问已授权，直接使用。
- **共享文件夹（谨慎使用）**：在 `/data` 下创建 mlusers 组共享目录（setgid + 组权限）：

```bash
DIR={FOLDER_NAME}; mkdir -p "$DIR" && chown root:mlusers "$DIR" && chmod 2775 "$DIR"
```
